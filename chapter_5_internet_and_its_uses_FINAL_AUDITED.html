5.1

Internet vs World Wide Web

Internet

The infrastructure: the global network/network infrastructure that allows devices and networks to communicate.

World Wide Web

The collection of websites and web pages that are accessed using the internet.

Critical distinction: the internet and WWW are not synonyms. The web uses the internet's infrastructure.

URL, HTTP and HTTPS

A uniform resource locator (URL) is a text-based address for a web page. The syllabus expects recognition of its components: protocol, domain name and web page/file name.

https://www.example.com/index.html
PartMeaning
ProtocolRules/protocol used for communication, e.g. HTTP or HTTPS.
Domain nameHuman-readable name used to identify the website/domain.
Web page/file nameIdentifies the requested resource/page/file.

HTTP and HTTPS

HTTP is the protocol used to transfer web-page data. HTTPS provides secure transfer; the supplied papers connect secure web communication to SSL, encrypted transmission and digital-certificate validation.

HTTP vs HTTPS — exam depth: HTTP provides the rules for requesting/transferring web-page data. HTTPS is the secure form used when transmitted data needs protection. Supplied papers connect a secure web connection with encryption, SSL and digital-certificate authentication; HTTPS/SSL protects data in transmission rather than making the website itself automatically trustworthy.

Web browser

The main purpose of a web browser is to render HTML and display web pages.

Browser functionWhat it does
Bookmarks/favouritesStores links to pages for later access.
HistoryRecords pages/sites previously visited.
Multiple tabsAllows multiple web pages to be open in one browser window.
CookiesStores/manages cookie data used by websites.
Navigation toolsProvides controls for moving through browsing history/pages.
Address barAllows a URL/address to be entered.
Browser functions required by the syllabus: A web browser's main purpose is to render HTML and display web pages. It can also store bookmarks/favourites, record user history, allow multiple tabs, store/manage cookies, provide navigation tools and provide an address bar.

How a web page is located, retrieved and displayed

1User enters a URL in the web browser.
2The URL/domain is sent to a domain name server (DNS).
3DNS searches for the matching IP address.
4If not found, the request can be passed to another DNS.
5The matching IP address is returned to the user's device/browser.
6The browser/device sends a request to the web server.
7The web server sends the requested web-page / HTML data.
8The browser renders the HTML and displays the page.
Examiner lens: supplied MS repeatedly rewards the complete chain URL → DNS → IP address → web server request → HTML/web-page data → browser rendering.
Full retrieval chain from the supplied MS: The browser sends the URL/domain to a DNS; the DNS searches for the matching IP address; if it cannot find the URL it can pass the request to another DNS; the IP address is returned; the browser/device sends a request to the web server; the server returns the web page/HTML data; and the browser renders the HTML to display the page.

Cookies

Cookies are small pieces/files of data used by websites and stored/managed by the browser. The syllabus explicitly includes saving personal details, tracking user preferences, holding shopping-cart items and storing login details.

Session cookie

Temporary. Associated with the current browsing session; supplied MS evidence describes it as stored in memory/RAM and lost when the browser is closed.

Persistent cookie

Remains beyond the current session; supplied MS evidence describes it as stored in secondary storage and remaining until it expires or is deleted.

Cookie use — syllabus checklist: Cookies can save personal details, track user preferences, hold items in an online shopping cart and store login details. A session cookie is temporary and is lost when the browser/session ends; supplied MS evidence describes it as stored in memory/RAM. A persistent cookie remains after the session, normally in secondary storage, until it expires or is deleted.
5.2

Digital currency & blockchain

A digital currency exists only electronically rather than physically. It can be accessed/used electronically.

Blockchain

At this syllabus level, blockchain is a digital ledger: a time-stamped series of records that cannot be altered. Supplied mark-scheme evidence expands the process:

1A transaction is made using digital currency.
2The transaction is stored as a new set/block of data.
3It is given a time-stamp.
4It is linked to the previous set/block of data.
5Existing transactions cannot be altered; new transactions are added.
6This creates a traceable record/ledger of transactions.
Source wording worth learning: blockchain is a decentralised digital ledger/database in which transactions are time-stamped, linked to previous data and cannot be altered.
Blockchain — answer chain: Digital currency exists only electronically. Blockchain records transactions in a digital ledger. Transactions/records are time-stamped, new records are linked into the existing chain/ledger and existing records cannot simply be altered. This provides a traceable record of digital-currency transactions.
5.3

Cyber-security threats

For every threat, students need both the process (how it happens) and the aim/effect (what the attacker is trying to achieve).

ThreatProcess / central idea
Brute-force attackRepeatedly tries possible credentials/password combinations until a valid one is found; aims to gain unauthorised access.
Data interceptionData being transmitted is captured/read by an unauthorised party; the attacker may obtain confidential information.
DDoSMany compromised devices/bots send large numbers of requests to a target simultaneously, overwhelming the server/service and preventing legitimate access.
HackingGaining unauthorised access to a computer/system/network, potentially to view, alter, steal or damage data/resources.
VirusMalicious code attached to/in another file/program; can replicate/spread when the host is executed.
WormMalware capable of self-replicating and spreading across networks without needing a host file in the same way as a virus.
Trojan horseMalware disguised as legitimate/useful software to persuade a user to install/run it.
SpywareSecretly monitors/collects user activity or data and passes it to another party.
AdwareDisplays unwanted advertising, often based on/associated with user activity.
RansomwarePrevents access to data/system, commonly through encryption/locking, and demands payment.
PharmingRedirects a user to a fraudulent website, even when the intended address is used, in order to obtain data such as credentials.
PhishingFraudulent communication impersonates a trusted source and attempts to persuade the victim to reveal data or follow a malicious link.
Social engineeringManipulates/deceives people rather than directly attacking technology, to make them disclose information or perform an unsafe action.
DDoS — full process: Malware can turn many computers/devices into bots, forming a botnet. The attacker causes the bots to send large numbers of requests simultaneously to a web server. The server becomes overloaded/can crash, so legitimate users cannot access the website/service.
Threat precision: Hacking is gaining unauthorised access to a computer/system. A brute-force attack repeatedly tries password/key combinations until one succeeds. Data interception captures data while it is being transmitted. Phishing uses fraudulent communication to trick a user into disclosing data or following a malicious link; pharming redirects a user to a fraudulent site even when an apparently correct address is used. Social engineering manipulates people into revealing information or performing an unsafe action.
Malware distinctions: A virus attaches to/infects files or programs and replicates when the host is run; a worm self-replicates and spreads across networks; a Trojan horse appears legitimate but contains malicious code; spyware secretly monitors/collects user data; adware displays unwanted advertising and may track behaviour; ransomware blocks/encrypts access to data and demands payment.

Security solutions

SolutionHow it helps
Access levelsRestrict users to data/resources they are authorised to use.
Anti-malwareDetects, blocks/quarantines and/or removes malicious software; syllabus includes anti-virus and anti-spyware.
Username + passwordAuthenticates a user using credentials.
BiometricsAuthenticates using a physical/behavioural characteristic of the user.
Two-step verificationRequires a second authentication step, reducing reliance on one compromised credential.
Automatic software updatesApplies security fixes/patches so known vulnerabilities are corrected.
Check spelling/toneUnusual wording, errors or tone can indicate a fraudulent/social-engineering communication.
Check URL on linksHelps identify links leading to fraudulent/unexpected domains.
FirewallExamines network traffic against criteria/rules; can reject traffic that fails them and block/close ports.
Privacy settingsRestrict what information is exposed and who can access it.
Proxy serverActs as an intermediary; can inspect/filter requests and prevent unwanted/suspicious traffic reaching the protected server/network.
SSLSupports secure web communication; supplied papers test encrypted connection and server identity through a digital certificate.
How Cambridge often awards explanation marks: identify the solution → state what it checks/does → link this to how the attack or unauthorised access is prevented.
Security-solutions checklist: The syllabus requires access levels; anti-malware including anti-virus and anti-spyware; authentication using username/password, biometrics and two-step verification; automatic software updates; checking the spelling and tone of communications; checking the URL attached to a link; firewalls; privacy settings; proxy servers; and SSL. In an explain question, link the solution to the threat it prevents/reduces.
Proxy server against DDoS — 2025 MS depth: A proxy examines incoming requests/transmissions. It can limit the number/rate of requests forwarded to the web server, use caching to answer a request without forwarding it, and block requests from a particular IP address. This reduces malicious traffic reaching the web server.
Firewall: A firewall monitors/checks incoming and outgoing network traffic against rules/criteria and blocks traffic that does not meet the rules. It therefore helps prevent unauthorised or suspicious connections; it is not the same thing as anti-malware software.

SSL secure-connection process

1Browser asks the web server to identify itself.
2Web server sends its digital certificate.
3Browser authenticates/validates the certificate.
4If valid, a secure/encrypted connection can be established and the transaction/data transfer can begin.
5Supplied MS links the encrypted connection to asymmetric encryption so intercepted data is meaningless.
6If the certificate is invalid, the connection is not treated as secure; the transaction can be rejected/cancelled or the user notified.
