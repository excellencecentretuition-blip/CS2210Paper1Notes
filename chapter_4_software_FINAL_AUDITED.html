4.1

System software vs application software

System software

Provides the services that the computer requires. The syllabus includes the operating system and utility software.

Its role is centred on managing/maintaining the computer system and providing the environment in which applications can run.

Application software

Provides the services that the user requires and allows the user to perform tasks.

Supplied MS examples include word processor, spreadsheet, database, web browser, image/photo editor, video editor, email client, game and social-media app.

Cambridge distinction: “system software is for the computer; application software is for the user” is a useful memory aid, but a stronger answer says what service each provides and gives a valid example.
MS depth — firmware: Firmware can permanently store instructions, including start-up instructions; provide the operating system with a platform to run on; control/manage communication with hardware; and store instructions securely so they are not easily corrupted. Supplied examples include bootstrap, bootloader and BIOS. System-software examples include the operating system and utility software.

Operating system: role and functions

The operating system is system software that manages the computer's main functions and provides the platform on which application software runs.

FunctionWhat it means in an answer
Managing filesOrganises/manages files and folders and operations involving them.
Handling interruptsResponds to interrupt signals and arranges for the appropriate interrupt-handling routine.
Providing an interfaceProvides the means by which the user interacts with the computer.
Managing peripherals and driversControls communication with peripheral hardware through appropriate drivers.
Managing memoryAllocates/manages RAM and can manage movement between RAM and virtual memory.
Managing multitaskingManages processor/memory resources so more than one process can make progress.
Platform for applicationsProvides the environment/services needed for application software to run.
System securityHelps control and protect access to the computer/system resources.
User accountsManages users and their access to the system.
Common trap: the bootstrap is not an OS function. Firmware/bootloader starts the chain that allows the OS to run.
OS answer depth: Supplied papers test individual OS functions in context. For memory, accepted ideas include managing/allocating memory, managing multitasking and movement of data between RAM and virtual memory. Do not describe loading the bootstrap as an operating-system function: the bootloader/bootstrap is firmware used during start-up.

Firmware is software stored so that essential instructions remain available. Supplied mark schemes accept examples such as BIOS, bootstrap and bootloader, and describe firmware as providing the operating system with a platform to run on and controlling/allowing communication with hardware.

Interrupts

An interrupt is a signal/request requiring processor attention. It allows an event to be dealt with rather than forcing the processor to continuously check every possible device/event.

Hardware interrupt

Generated by hardware. Syllabus examples: pressing a keyboard key and moving the mouse. Supplied papers also use mouse clicks and printer events.

Software interrupt

Generated by a software condition. Syllabus examples: division by zero and two processes trying to access the same memory location.

How an interrupt is handled

1An event generates an interrupt and it is sent to the processor.
2The interrupt is given/has a priority and may be placed in an interrupt queue.
3The processor completes the current FDE cycle / checks the interrupt and its priority.
4If it should be serviced, the current process/state is halted and stored, e.g. on a stack.
5The processor fetches the interrupt/checks its source.
6The interrupt service routine (ISR) / interrupt handler is called.
7The ISR is a sequence of instructions that handles the interrupt.
8After handling, the previous process can be restored/continued.
Examiner lens: Cambridge repeatedly rewards the chain priority → pause/store current process → ISR → handle → resume, not simply “the CPU deals with the interrupt.”
Interrupt sequence — full MS chain: An interrupt is given a priority and may be placed in an interrupt queue. The processor completes/checks its current processing stage as required, checks interrupt priority, and if the interrupt has higher priority it halts the current process and stores its state (a supplied 2025 MS explicitly credits storing it on a stack). It fetches/checks the interrupt/source and calls the interrupt service routine (ISR) / interrupt handler. If the interrupt does not have higher priority, the current process continues. After servicing, the interrupted process can resume.
Hardware vs software interrupts: Hardware examples required by the syllabus include a keyboard key press and mouse movement/click. Software examples include division by zero and two processes attempting to access the same memory location.
4.2

High-level and low-level languages

ComparisonHigh-levelLow-level
RepresentationEnglish-like statements / closer to human languageAssembly mnemonics or machine code/binary
Read/write/debugEasierMore difficult
Machine dependenceMachine independent / portableMachine dependent / not portable
Hardware controlCannot directly manipulate hardware to the same degreeCan directly manipulate hardware
Actions per statementOne line can perform multiple lower-level actionsOne low-level instruction performs a more direct/single action

The syllabus expects advantages/disadvantages through these axes: ease of reading/writing, ease of debugging, machine independence and direct manipulation of hardware.

MS comparison depth: High-level languages use English-like statements and are generally easier to read, write and debug; they are machine independent/portable, but do not directly manipulate hardware in the way low-level languages can. Low-level/assembly language uses mnemonics, is hardware/machine dependent, can manipulate hardware directly and can give closer control of memory/hardware. A high-level statement can represent several operations whereas a low-level instruction is much closer to a single machine operation.

Assembly language & assembler

Assembly language is a low-level language using mnemonics/symbolic instructions. An assembler translates assembly language into machine code.

Do not confuse the translators: assembly → assembler; high-level → compiler or interpreter.

Supplied papers test advantages such as memory efficiency and direct hardware manipulation. These are scenario-sensitive: the student should connect the advantage to why a low-level language is suitable for the task.

Assembly-language MS depth: Assembly is a low-level language that uses mnemonics and is translated to machine code by an assembler. Supplied marking points include direct manipulation/communication with hardware and, in suitable contexts, memory efficiency or faster execution.

Compiler vs interpreter

Compiler

  • translates the whole code at once before execution
  • produces an executable file
  • if errors are detected, produces an error report for the whole code / displays the errors
  • final program is commonly compiled when development is complete

Interpreter

  • translates and executes line by line
  • stops when an error is found
  • the error can be corrected before continuing
  • especially useful while developing/testing a program
Why interpreter during development? line-by-line translation/execution → stops at the error → programmer can identify/correct it immediately → useful for iterative development.
Compiler — exact process: A compiler translates the whole program/code at once before execution. It can produce an executable file. If errors are present, it produces an error report for the code rather than stopping after the first error.
Interpreter — development advantages from the supplied MS: It translates and executes one statement/line at a time; stops when an error is found; lets the programmer correct the error and continue from that point; does not need to retranslate all the code after that correction; can test sections of code; and can test before the whole program is complete/functional/accurate. These are why an interpreter is especially useful during development.
Final-program distinction: The syllabus expects the interpreter mainly during development, while a compiler is appropriate for producing the final translated/executable program.

Integrated Development Environment (IDE)

An IDE brings tools for writing, translating, running and debugging code together in one development environment.

IDE featureRole expected by Cambridge
Code editorAllows the programmer to write/change program code.
Run-time environmentAllows the code to run and the programmer to see its output.
TranslatorTranslates source code into the required lower-level/machine-code form.
Error diagnosticsFeatures used to find errors in code.
Auto-completionWhen a programmer starts a command word, the IDE suggests completion options.
Auto-correctionA misspelt command word can be changed to the correct spelling.
PrettyprintFormats code; supplied MS describes command words/identifiers being shown in different colours.
Common trap: when a question asks for “function and role”, naming auto-completion alone earns only the identification part; explain what it actually does.
